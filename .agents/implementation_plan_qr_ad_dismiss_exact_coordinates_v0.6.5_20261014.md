# 구현 계획서: QR 쇼핑 광고 X 버튼 정밀 실측 좌표 타격 및 센티넬 이중화 (v0.6.5)

## 1. 실패 원인 정밀 역추적 분석
사용자가 업로드한 실제 TV 사진(`media_1791889727056_1647e467.jpg`)을 16:9 1080p 화면 비율로 정밀 픽셀 역산한 결과, 기존 v0.6.2의 실패 원인이 명확히 규명되었습니다:

1. **타깃 X 닫기 버튼 터치 좌표 오류 (2배 이상 빗나감)**:
   - 기존 v0.6.2: `targetX = 25.5%`, `targetY = 79.3%`
   - **실제 정밀 실측값**: **`targetX = 12.4%` (0.124f)**, **`targetY = 89.3%` (0.893f)**
   - 기존 코드는 가로로는 X 버튼 오른쪽 허공(25.5%)을 찍었고, 세로로는 X 버튼보다 한참 위쪽인 카드 내부 글자(79.3%)를 찍고 있어서 X 버튼이 전혀 눌리지 않았습니다.
   - 실제로 X 버튼의 세로 높이(89.3%)는 우하단 스킵 버튼(89.5%)과 거의 동일한 수평 라인에 있습니다.
2. **픽셀 센서 ROI 왜곡**:
   - 기존 ROI (X: 10%~42%, Y: 50%~76%)는 실제 QR 카드(X: 3%~22%, Y: 45%~85%)의 좌측 절반과 하단부가 잘려 나가 있었습니다.
3. **센티넬 루프의 접근성 트리 조회 누락**:
   - 영상 재생 중 리모컨을 조작하지 않으면 `onAccessibilityEvent`가 오지 않으므로, 1.2초 주기의 센티넬 루프에서 직접 `rootInActiveWindow`를 확인하여 접근성 텍스트 기반 닫기도 함께 수행해야 합니다.

## 2. 해결 수술 계획

### 1) [TvAdSkipService.kt](file:///k:/AI_Projects/##%20안드로이드TV용%20유튜브%20광고%20스킵/app/src/main/java/com/example/tvadskipper/TvAdSkipService.kt)
- **정밀 실측 타깃 좌표 적용**:
  - `targetX = width * 0.124f` (12.4%)
  - `targetY = height * 0.893f` (89.3%)
  - 1차 중심점 터치 + 120ms 후 중심점 재터치 (Cobalt 웹뷰 터치 씹힘 원천 방지)
- **픽셀 센서 ROI 전면 재조정**:
  - `qrStartX = (width * 0.03f).toInt()` (3%)
  - `qrEndX = (width * 0.22f).toInt()` (22%)
  - `qrStartY = (height * 0.45f).toInt()` (45%)
  - `qrEndY = (height * 0.85f).toInt()` (85%)
- **센티넬 루프 이중 감지 파이프라인**:
  - 센티넬 주기: `1200ms` (1.2초)
  - 1차: `rootInActiveWindow`에서 QR 키워드 발견 시 즉시 X 버튼 타격
  - 2차: 노드가 비어있더라도 `takeScreenshot` 픽셀 센서로 QR 코드 카드 검출 시 즉시 X 버튼 타격
