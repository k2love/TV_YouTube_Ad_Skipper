# [계획서] 유튜브 전용 볼륨 제어 개편 및 실시간 런타임 로그 진단 시스템 (v0.5.3)

## 1. 개요 및 배경
- **문제 인식**:
  1. **TV 하드웨어 볼륨 간섭**: 기존 볼륨 제어가 `AudioManager.STREAM_MUSIC` (TV 본체 시스템 볼륨)을 조작하여 화면에 볼륨 OSD 바가 표시되고, 본체 볼륨이 0이나 5로 낮아져 TV 전체 음량이 줄어드는 문제 발생. 사용자는 TV 볼륨은 리모컨으로 독립 제어하고 **유튜브 앱 자체의 볼륨만 제어**되기를 원함.
  2. **광고 5~6초 조기 복원 버그**: 강제 광고(비건너뛰기 광고) 재생 중 5초 시점에 스킵 버튼 이벤트(`isSkipEnabled`) 또는 스킵 시도가 발생하면서 `sendSkipAdCommand()` 내부에서 즉시 `restoreAudio()`를 호출해 광고 중간에 볼륨이 복원되는 현상.
  3. **2연속 강제 광고(15초+5초 Ad Pod) 무음 실패 및 볼륨 0 잔존**: 1차 광고 종료와 2차 광고 시작 사이의 브릿지 타이밍 엇갈림으로 본 영상 진입 시 볼륨이 0으로 유지되는 현상.
  4. **광고 건너뛰기 미동작 사태**: 전체화면 재생 시 시스템 오버레이(`android`) 윈도우 필터링 차단으로 인한 접근성/센서 클릭 정지.
  5. **현장 진단 로그 부재**: TV 현장의 볼륨 수치와 Lounge 통신 패킷 흐름을 확인할 수 없음.

## 2. 해결 전략 및 수술적 변경점
1. **유튜브 앱 자체 볼륨(0~100) 전용 제어로 전면 개편**:
   - TV 하드웨어 시스템 볼륨(`AudioManager`) 조작을 완전히 배제하고, Lounge 프로토콜의 `setVolume` 명령만 전송 (`sendSetVolumeCommand(0)` / `sendSetVolumeCommand(100)`).
   - TV 화면에 불필요한 안드로이드 볼륨 바 OSD가 뜨지 않으며, TV 자체 볼륨 설정은 사용자가 리모컨으로 자유롭게 조절.
2. **광고 5~6초 조기 복원 원천 차단**:
   - `sendSkipAdCommand()` 발송 직후 `restoreAudio()`를 호출하던 로직을 제거.
   - 실제 광고 종료 이벤트(`STOPPED`/`ENDED` or `onStateChange`)가 유튜브 서버로부터 수신될 때만 볼륨을 복원하도록 가드.
3. **2연속 강제 광고(15초+5초) 4초 브릿지 및 본 영상 100% 복원 보장**:
   - 광고 1 슬롯 종료 후 4.0초 동안 추가 광고 여부를 대기하여 2차 광고 시작 시 무음을 끊김 없이 연속 유지.
   - 모든 광고 종료 확인 또는 본 영상 재생 감지 시 유튜브 볼륨을 100%(또는 광고 전 볼륨)로 확실 복원.
4. **실시간 파일 로거 및 진단 UI 탑재**:
   - `AppLogger.kt`: `filesDir/ad_skipper_runtime.log`에 실시간 이벤트, 볼륨 수치, 스킵 동작 누적 기록 (최대 2MB 자동 관리).
   - 메인 화면에 `[📄 실시간 로그 보기]` (리모컨 스크롤 팝업) 및 `[📤 로그 파일 공유/내보내기]` (FileProvider 연동) 버튼 제공.
5. **버전 빌드업 및 무결점 단일 APK 배포**:
   - `versionCode = 53`, `versionName = "0.5.3"`.
   - `TV_YouTube_Ad_Skipper.apk` 갱신.
