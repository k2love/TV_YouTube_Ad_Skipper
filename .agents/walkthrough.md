# 검증 및 수술 결과 리포트 (v0.5.9)

## 1. 수술 배경
사용자께서 **"강제 광고(5초, 15초, 20초, 30초)가 나올 때 볼륨을 0으로 줄인 뒤, 3~4초 만에 바로 볼륨이 100으로 다시 높아지는 경우가 대부분이다. 광고가 끝날 때까지 0을 유지하다가 영상이 시작되면 100으로 올려달라"**는 피드백을 주셨습니다.
런타임 패킷과 소스 코드를 면밀히 분석하여, 광고 시작 후 3~4초 시점에 소리가 복원되던 치명적인 3대 원인을 규명하고 정밀 수술을 완료했습니다.

---

## 2. 규명된 근본 원인 및 수술 내역

### 1) [원인 1 - 핵심 범인] `adState == "0"`을 광고 종료로 오인
- **원인**: 유튜브 TV는 광고 시작 시 `currentTime=0`, `adState="0"`, `isSkipEnabled="false"`를 전송합니다.
  - `adState="0"`은 광고 종료가 아니라 광고 재생 시작 초기화(INIT/UNSTARTED) 상태코드입니다.
  - 기존 코드는 `adState == "0"`을 광고 슬롯 종료로 오인하여 1.0초 뒤 볼륨을 100으로 복원하도록 예약했습니다. (광고 시작 2초 시점에 패킷 수신 -> 3~4초 시점에 소리가 터져 나오던 정확한 원인!)
- **수술**: 
  - `adState == "0"`을 광고 종료 조건에서 완전히 제거하고, 광고 진행 중(`adIsPlaying`) 조건에 편입시켰습니다.
  - 실제 종료는 오직 `adState == "1082"`, `"STOPPED"`, `"ENDED"`만 인정합니다.

### 2) [원인 2] `nowPlaying` 패킷 내 본 영상 `videoId` 오탐
- **원인**: 광고가 재생 중일 때도 구글 서버는 `nowPlaying` 패킷을 주기적으로 보냅니다.
  - 이 패킷에는 본 영상의 `videoId`가 항상 포함되어 있으며, 광고 중일 때는 `adState="1"`, `adVideoId="..."`가 함께 실려 옵니다.
  - 기존 코드는 `videoId.isNotEmpty()`만 보고 광고 중인지 검사하지 않은 채 본 영상 시작으로 착각하여 볼륨을 100으로 강제 복원했습니다.
- **수술**:
  - `nowPlaying` 수신 시 `adState` 또는 `adVideoId`가 들어있으면 광고 진행 중으로 확정하여 음소거를 계속 유지하고, **광고 필드가 완전히 사라지고 `!isAdPlaying`일 때만 순수 본 영상으로 판단하여 복원**하도록 수정했습니다.

### 3) [원인 3] `onStateChange: state=1` 오탐 (광고 비디오 자체의 재생)
- **원인**: 광고 비디오 자체도 플레이어 관점에서는 `state=1` (PLAYING)으로 재생됩니다.
  - 광고 비디오가 재생 시작되자마자 날아온 `state=1`을 보고 본 영상이 시작되었다고 오인하여 볼륨을 복원해 버렸습니다.
- **수술**:
  - `state == 1` 수신 시에도 반드시 **`!isAdPlaying` 조건이 충족될 때만** 볼륨을 100으로 복원하도록 격리했습니다.

### 4) [원인 4] 안전 타이머의 20초 한계
- **수술**:
  - 기존 `delay(20000)` 안전 타이머를 **`delay(45000)` (45초)**로 확장하여 30초 강제 광고 및 15초+15초 연속 강제 광고도 끝까지 완벽하게 커버하도록 개선했습니다.
